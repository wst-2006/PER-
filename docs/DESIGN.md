# PER 量化研究系统：总体设计（v0.1）

状态：草案，待 T001–T004 结果回传后修订。带「待验证」标记的内容是假设，不是结论。

## 0. 目标与非目标

**目标**

- 全市场 A 股截面选股，输出每日**指令单**：买卖哪些股票、各多少股。人只负责照单执行和最终复核。
- 回测、纸面验证、每日出单使用**同一套引擎**。
- 因子打分由模型滚动训练，并持续监控衰减。
- 全部结论可复现、可审计，能作为求职时的研究与工程作品。

**非目标**

- 不自动下单，不连接券商。
- 不做日内和高频。信号在 D 日收盘后生成，D+1 执行。
- 不承诺收益。40% 年化是个人目标，不是系统验收标准；系统的验收标准是第 5 节的研究门禁。
- 当前阶段只做纸面验证，不涉及真实资金。

## 1. 设计原则

1. **时点正确优先于一切。** 任何特征只能使用信号时点已公开的数据。
2. **原始数据只追加、不覆盖**，每条记录带获取时间。
3. **回测与实盘同构。** 每日指令单就是回测引擎多走一步的输出。
4. **选股与择时分开评估。** 选股看超额收益，择时单独立项。
5. **先定门禁、再看结果。** 门禁阈值在跑实验之前冻结。
6. **每个实验都登记**，包括失败的。
7. **简单方法先行。** 基线不成立之前不上复杂模型。

## 2. 架构

```
Tushare ──> raw（只追加） ──> curated（时点安全） ──> features / labels
                                                        │
                                   research（walk-forward、实验登记）
                                                        │
                                                   model artifact
                                                        │
        engine（事件驱动：成交、费用、T+1、涨跌停、停牌、整手）
            │                         │
        backtest                 daily run ──> 指令单 + 纸面账本
                                                        │
                                               web（只读看板，最后做）
```

目录：

```
perq/            核心包（设计方编写，受保护）
  data/          raw 写入、curated 构建、数据质量检查
  features/      特征与标签
  research/      切分、评估、实验登记
  engine/        回测与每日出单
  portfolio/     组合构建、仓位、风控
scripts/         命令行入口
tests/           测试（受保护）
tools/           完整性校验等工具（受保护）
tasks/           任务单
results/         每个任务回传的小体积摘要（JSON/CSV，入库）
docs/            设计与决策记录
```

## 3. 数据层

### 3.1 存储

- 研究数据：**Parquet + DuckDB**。数据根目录由 `PERQ_DATA_DIR` 指定，不入库。
- 网站状态（持仓、指令、日志）：SQLite，后期如有需要再换。
- 旧 PostgreSQL 不继承为主存储。T003 盘点后决定哪些表可作为交叉校验源。
- 机器内存 16 GB 且日常占用高：DuckDB 设 `memory_limit`（初值 6 GB），所有全市场计算按日期分块，禁止一次性把全表读进 pandas。

### 3.2 分层

| 层 | 路径 | 规则 |
| --- | --- | --- |
| raw | `raw/<接口>/<分区>.parquet` | 接口原样落盘，追加 `_fetched_at`；同一分区重新拉取时写新文件，不覆盖 |
| curated | `curated/<表>/` | 去重、类型统一、时点对齐后的干净表；可由 raw 完全重建 |
| features | `features/<版本>/date=YYYYMMDD/` | 每个版本不可变，带特征清单和哈希 |
| labels | `labels/<版本>/date=YYYYMMDD/` | 同上 |

### 3.3 范围

- 时间：行情自 2014-01-01 起（2014 年用于特征预热，研究样本自 2016-01 起）。「待验证：以 T002 探测到的各接口实际历史深度为准」
- 股票：上市、退市、暂停上市**全部纳入**，避免幸存者偏差。
- 板块：沪深主板、创业板、科创板、北交所全部进入数据层；是否进入可交易股票池由第 3.5 节规则决定。

### 3.4 需要的数据（T002 逐项探测）

- 基础：股票列表（含退市）、交易日历、曾用名（还原历史 ST 状态）、停复牌。
- 行情：日线、复权因子、每日指标（换手、市值、估值）、涨跌停价。
- 资金与交易行为：个股资金流、龙虎榜、融资融券、涨跌停与炸板统计。
- 财务：三大报表、财务指标、业绩预告、业绩快报、分红。必须有**实际公告日**字段。
- 行业与指数：申万行业分类及历史成分、主要指数日线与成分权重。
- 股东与事件：股东户数、增减持、回购、限售解禁。
- 可选：分钟线（用于校准开盘成交假设）、卖方盈利预测。

### 3.5 可交易股票池（每日重算）

剔除：ST 与 *ST、退市整理期、当日停牌、上市不足 120 个交易日、近 20 日日均成交额低于阈值（初值 3000 万元，待回测检验）。

被剔除的股票仍留在数据里，只是不进入候选。已持有的股票被剔除时按风控规则处理，不是直接消失。

### 3.6 数据质量检查（每次同步后自动运行）

- 每个交易日的行数与当日上市股票数的偏差。
- 复权价连续性：复权后单日涨跌幅超出涨跌停幅度的记录。
- 涨跌停价与收盘价的一致性。
- 各接口之间股票代码与交易日的对齐。
- 财务数据公告日早于报告期末、或晚于合理披露期限的记录。

任何一项超阈值，当日流程停止，不出指令单。

## 4. 特征与标签

### 4.1 标签

- 信号在 D 日收盘后生成，D+1 开盘买入。
- 持有期 h ∈ {5, 10, 20} 个交易日。
- 原始收益：`复权开盘价[D+1+h] / 复权开盘价[D+1] − 1`（开盘到开盘，与引擎的换仓时点一致）。
- **训练标签**：原始收益减去当日股票池等权收益，再对行业哑变量和对数市值做截面回归取残差。
- 同时保存可交易性标记：D+1 开盘是否涨停买不进、退出日是否跌停卖不出、期间是否停牌。
- 「待验证」如果分钟线可得，用 D+1 开盘后 30 分钟均价替代开盘价做敏感性检验。

### 4.2 特征族（第一版）

价格动量与反转、波动与下行风险、流动性与换手、市值与估值、资金流、行业相对强弱、涨跌停与连板行为、财务质量与成长（按公告日对齐）、业绩预告与快报事件、股东与解禁事件。

每个特征入库前必须通过：缺失率、时点安全检查、单因子 IC 与分组单调性报告。

### 4.3 截面处理

每日截面内：去极值（MAD）、标准化、缺失值按行业中位数填充并保留缺失标记。所有统计量只用当日截面，不跨日。

## 5. 研究协议

### 5.1 时间切分

| 区间 | 用途 |
| --- | --- |
| 2016-01 至 2024-12 | 开发区：特征筛选、模型选择、参数确定，全部在此区间内做 walk-forward |
| 2025-01 至 2026-06 | 确认区：模型冻结后只跑一次 |
| 2026-07-01 至冻结日 | 盲测区：没有任何旧研究接触过，最后只开一次 |
| 冻结日之后 | 前向纸面验证，至少 60 个交易日 |

说明：设计方读过旧项目文档，知道 2026 年 1 至 3 月对短线多头是失败窗口，所以确认区存在轻微信息污染。盲测区和前向纸面是干净的。

### 5.2 Walk-forward

- 扩展或滚动训练窗，验证窗 3 个月，逐窗前推。
- 训练集与验证集之间留出间隔，长度不小于标签持有期，防止标签重叠泄漏。

### 5.3 评估指标

- 因子层：Rank IC 均值、IC 的 t 值、IC 胜率、分组收益单调性。
- 组合层：相对基准的年化超额、信息比率、最大回撤、换手率、扣费后净值；按年份和市场状态分段报告。
- 基准：股票池等权（主）、中证 1000 与中证 2000（参考）。
- 对照：随机选股、20 日动量、小市值。模型必须显著好于全部对照。

### 5.4 门禁（初值，在 M3 开始前冻结，之后不得因结果修改）

- 开发区 walk-forward：Rank IC 均值 ≥ 0.03 且 t 值 > 3；扣费后年化超额为正的年份占比 ≥ 70%。
- 确认区：扣费后超额为正，且最大超额回撤不超过开发区最差年份的 1.5 倍。
- 盲测区：扣费后超额为正。
- 任一门禁不过：记录结论，回到开发区；盲测区一旦打开就视为已用掉，需要等待新的数据累积成新的盲测区。

### 5.5 实验登记

每次实验写入 `results/experiments/` 一条记录：数据版本哈希、特征清单、参数、随机种子、全部指标、结论。失败的实验同样登记。最终报告披露试验总次数。

## 6. 引擎

回测与每日出单共用。

- **时序**：D 日收盘后计算目标持仓，生成 D+1 指令；D+1 按成交模型撮合。
- **成交价**：D+1 开盘价加滑点（参数，初值单边 0.1%，待用分钟线校准）。
- **涨跌停**：开盘价等于涨停价则买入失败；开盘价等于跌停价则卖出失败并顺延到次日。使用接口提供的实际涨跌停价，不按比例推算。
- **停牌**：停牌日不成交，指令顺延。
- **T+1**：当日买入的股票当日不可卖。
- **整手**：主板与创业板买入为 100 股整数倍；科创板 200 股起、1 股递增；北交所 100 股起、1 股递增。卖出允许一次性卖出零股。「待验证：以交易所现行规则为准」
- **费用**（按日期生效）：
  - 佣金：费率为参数，双向收取，单笔最低 5 元。
  - 印花税：仅卖出，2023-08-28 起 0.05%，此前 0.1%。
  - 过户费：双向，2022-04-29 起 0.001%，此前 0.002%。
- **公司行为**：持仓按复权因子调整，分红送转不产生虚假收益。
- **退市**：进入退市整理期前按规则强制卖出；无法卖出的按最后可成交价结算并记入损失。
- **流动性上限**：单只成交额不超过该股近 20 日日均成交额的一定比例（初值 2%）。

引擎的每条规则都有对应的构造样本测试（例如：买入次日跌停、连续一字跌停、停牌跨越退出日、除权日）。

## 7. 组合与风控

### 7.1 组合构建

- 从模型评分最高的股票中选取 N 只（N 为回测参数，初始范围 15 至 30）。
- 换手缓冲：已持有的股票只要评分仍在前 2N 名就继续持有，降低无效换手。
- 行业上限：单一申万一级行业权重不超过 25%（初值）。

### 7.2 仓位

```
单只目标股数 = floor( 账户净值 × r ÷ (止损距离 × 价格) ÷ 每手股数 ) × 每手股数
```

- r：单笔风险，初值 0.4%，上限 2%（用户硬约束）。
- 止损距离：k × ATR(20) ÷ 价格，k 初值 2.5。
- 再受三个上限约束：单只权重上限（初值 8%）、行业上限、流动性上限。

### 7.3 退出

按优先级：风控强制卖出 → 个股止损（按收盘价判断，次日开盘执行）→ 评分跌出前 2N 名 → 持有期满且评分不在前 N 名。不设固定止盈。

### 7.4 组合层风控

- 回撤阶梯：组合净值从高点回撤达到第一档时目标仓位减半，达到第二档时清仓并冷却若干交易日。两档阈值为回测参数。
- 市场状态开关：独立模块，独立评估。只有当它在开发区和确认区都改善了风险调整后收益时才启用。

以上所有初值都是待检验的假设。

## 8. 模型

- 基线：截面线性模型（岭回归）与 LightGBM，CPU 训练，固定随机种子，保证结果可逐位复现。
- 多个持有期各训练一个模型，评分加权合成。
- 重训频率：每月一次（参数）。
- 衰减监控：线上滚动 IC 低于历史分布下沿时告警，触发复查而非自动换模型。
- GPU 仅在基线通过门禁之后，用于更大的模型族比较。

## 9. 每日流程与指令单

```
同步数据 → 数据质量检查 → 构建特征 → 模型评分 → 组合与风控 → 生成指令单 → 结算昨日纸面账本
```

任何一步失败则整体停止，不输出指令单。

指令单字段：日期、数据与模型版本哈希、市场状态、每条指令的代码、名称、方向、股数、参考价、占净值比例、止损价、入选或退出原因、风险提示。

纸面账本每日冻结，写入后不可修改。

## 12. 已知风险与未验证假设

1. Tushare 各接口的实际权限和历史深度未知，尤其是财务数据的公告日与修订记录、历史 ST 状态、分钟线。T002 解决。
2. 开盘价成交假设在小盘股上可能偏乐观，需要分钟线校准；没有分钟线则只能用更保守的滑点。
3. 设计方无法直接访问真实数据，依赖回传摘要。对策见 `AGENTS.md` 的回传规范。
4. 16 GB 内存对全市场十年数据的截面计算偏紧，实现上必须分块。
5. 2016 年以来 A 股经历注册制、涨跌停制度、印花税等多次规则变化，引擎按日期处理已知的几项，可能仍有遗漏。
6. 小市值风格在 A 股长期有效但尾部风险极大（如 2024 年初）。基准与中性化的选择会显著影响结论，报告中两种口径都要给出。
7. 可能的结果之一是：严格检验后没有发现可交易的超额。这种情况下项目产出是一套可信的研究平台和一份诚实的阴性结论。
