## 4. 与预期不符之处

### 4.1 baostock 早年份不是"没有权限"，而是"没有数据"

三次 `error_code` 都是 `0`（成功），却返回 0 行。这说明 baostock 对超范围查询不报错，静默返回空。**如果只看 error_code 会误判成"有权限但当天停牌"**。实际起点见 3.4：2020-01-02。

### 4.2 `is_new='N'` 对未变更过的股票返回空表，容易误判

`is_new='N'` 参数名是对的（官方文档：`is_new` 是否最新，默认 Y）。但用 `ts_code=000001.SZ` 查时为 0 行——因为平安银行从未变更过申万行业，没有"已剔除"的记录可返回。换成 000004.SZ 就有 3 行，`out_date` 全部非空（2008-12-30 至 2021-07-29）。

**结论：历史行业成分能取到，但只有真正发生过变更的对象才有行。** 若只看 000001.SZ 的 0 行，会得出"接口不支持历史"的错误结论。

### 4.3 银行板块在 `index_member_all` 里没有任何剔除记录

四个一级行业对比：农林牧渔 60 条、电子 174 条、计算机 47 条、**银行 0 条**。三个行业都有大量历史剔除记录，唯独银行一条没有。这不像接口问题（同参数同接口），更像数据侧缺失或银行板块确实从未调整成分。我无法从接口侧进一步判定，留作问题。

### 4.4 `index_member`（旧接口）比 `index_member_all` 历史更全

`index_member(ts_code=000001.SZ)` 返回 50 行、`out_date` 非空 41 行、最长到 2025-12-31；而 `index_member_all` 对同一只股票返回 0 行。两个接口口径不同，做行业历史时值得对照使用。

### 4.5 `bak_basic`、`broker_recommend` 在 2020 年为空

2020-01-02 / 2020-01 都是 0 行，2021 年起有数据。与 T002 里 2026 年正常返回形成对比，说明这两个接口不是"全历史"。

## 6. 问题与建议

### 6.1 用 `error_code` 判断 baostock 是否有数据会出错

必须同时判 `len(rows)>0`。建议设计方在数据层封装时统一按"行数为 0 即视为无数据"，不要信任 `error_code`。

### 6.2 免费分钟线只有 2020 年起，约 6.9 年

如果蓝图里的分钟级研究需要覆盖 2019 年及以前（例如 2015 股灾、2018 熊市），baostock 帮不上；只能上 Tushare 的付费历史分钟（2000 元/年，2009 年起）。

### 6.3 `dc_member`、`kpl_concept_cons`、`repurchase` 疑似触顶

三者在不同日期都返回整数上限（8000 / 3000 / 2000）。若要把它们当全量数据用，必须分页或按代码循环，不能一次调用就当成全市场。

### 6.4 行业的"历史归属"要用对接口

`index_member_all` 只对变更过的对象返回历史行；`index_member`（旧）对同一只股票给出 50 行、41 条剔除记录。建议设计方明确用哪个口径，并在数据层做"无记录 = 未变更"的兜底，否则会把 0 行误读成缺失。

### 6.5 银行板块 0 条剔除记录需要设计方判断

见 4.3。若行业历史对回测重要，建议单独核对银行板块口径。
